# HHC 管理者ガイド

認証を有効化した HHC（`HHC_AUTH=1`）を運用する管理者向けの手順書です。アプリ更新に合わせて本書も更新します。

## 1. 有効化と前提

`HHC_AUTH=1` で**全体がログイン必須**になります。必要なシークレット（Codespaces or `.env`）:

```
HHC_AUTH=1
HHC_DB_KEY=<強いパスフレーズ>            # 暗号化DBの鍵。紛失=復旧不可、変更=既存DB読めず
HHC_SESSION_SECRET=<openssl rand -base64 48>
HHC_ADMIN_EMAIL=you@example.com         # 最初の管理者
HHC_ADMIN_INITIAL_PASSWORD=<初期PW>     # 初回ログインで変更必須
# 任意: SMTP_*（招待メール／メールMFA）, HHC_AUDIT_RETENTION_DAYS, HHC_SIEM_*
```

> いずれか欠けると起動を拒否（`auth_misconfigured`）。詳細・全変数は [ARCHITECTURE.md](ARCHITECTURE.md) と `.env.example`。

## 2. 初回セットアップ

1. 上記を設定して起動（`npm run serve` 推奨。ログに `auth=true`）。
2. 起動時に最初のAdminが自動作成（ログに `bootstrap admin created: <email>`／**パスワードは出力しません**）。
3. 公開URL（配信モードなら `8787`）を開く → ログイン画面。
4. `HHC_ADMIN_EMAIL` ＋ 初期パスワードでログイン → **パスワード変更** → **MFA登録**（TOTPはQR、メールはコード）。
5. 以後 `/admin` で運用。

## 3. ユーザー管理（`/admin` → ユーザー管理）

- **招待して追加**：メアド＋ロールを入力 → **初期PWは発行されません**。
  - 招待リンクが画面に表示されます。SMTP設定済みなら**招待メールを自動送信**、未設定なら**リンクを本人へ手動共有**。
  - 本人はリンクから「パスワード設定 → MFA設定」を実施（受諾でアカウント有効化）。リンクは**72時間・単回利用**。
- **招待を再送**：招待中ユーザーに新しいリンクを再発行（旧リンクは無効）。
- **ロール変更**：Admin / User（自分自身と「最後の有効なAdmin」は降格不可）。
- **無効化 / 有効化**：無効化で即時セッション失効・ログイン不可。
- **パスワード再発行**：一時パスワードを発行（その場で1回だけ表示。本人は次回ログインで変更）。※招待方式と分離（MFA迂回防止）。
- **MFA再登録**：MFAをリセットし再登録を強制（セッションも失効）。

### ロールの権限
- **User**：解析・OSINT・レポート・案件履歴など通常機能。
- **Admin**：上記＋ユーザー管理＋監査ダッシュボード。

## 4. MFA（多要素認証）

- **TOTP**（Google Authenticator 等）：登録時のQR／手動シークレットで設定。SMTP不要・オフライン可・**推奨**。
- **メールコード**：ログイン毎にワンタイムコード送信。**SMTP設定が必要**。チャレンジ画面に**再送ボタン（クールダウン付き）**。
- SMTPが使えない/送信失敗時は明示表示。閉域ではTOTPを推奨。

## 5. 監査ログ（`/admin` → 監査ログ）

- **区分タブ**：すべて／**認証**（ログイン・MFA・ログアウト等）／**操作**（OSINT・レポート・履歴保存等）／**管理**（ユーザー操作・監査閲覧）。
- **記録項目**：日時・ユーザー・操作（action）・ステータス・アクセス元IP・ロケーション（Geo）・User-Agent・**詳細**。
  - 詳細＝**処理後にAPIへ投げた検索キー**（OSINTの会社/ドメイン/氏名/肩書き等）。**貼付本文・パスワード・MFAコードは記録しません**。
- **フィルタ**：期間・操作・メアド。**ページング**。
- **保持期間**：`HHC_AUDIT_RETENTION_DAYS`（既定30日）を超えた行を**毎日自動削除**（0で無期限）。現在値は画面に表示。
- **エクスポート**：フィルタ条件のまま **CSV / JSON** をダウンロード。
- **SIEM転送**：`HHC_SIEM_URL` 設定時、各イベントを **Splunk HEC**（`HHC_SIEM_FORMAT=splunk`、`HHC_SIEM_TOKEN`）または**汎用JSON Webhook**（`=json`）へ転送（失敗してもローカル記録は維持）。

## 6. 運用・バックアップ・復旧

- **バックアップ**：UIの「案件履歴」→ **暗号化エクスポート(.age)**（`HHC_DB_KEY` で復号）。サーバ移行は同じ鍵でインポート。
  - ※アカウント・監査は `.age` に含まれません。これらも残すなら `data/hhc-cases.db` ごと（暗号化済み）退避し、鍵は別管理。
- **停止/再起動**：シークレット変更後は再起動（Codespacesは Rebuild / Stop→Start）。`data/` は保持。
- **鍵の管理**：`HHC_DB_KEY` を失うと全データ復旧不可。安全に保管・変更しない。

## 7. トラブルシュート

| 症状 | 対処 |
|---|---|
| 起動時 `auth_misconfigured` | `HHC_DB_KEY` / `HHC_SESSION_SECRET` 等の必須シークレット不足。設定して再起動 |
| ログイン画面が出ない（`auth=false`） | シークレット未注入。Rebuild / Stop→Start（[起動ガイド](起動ガイド.md)参照） |
| 招待メールが届かない | SMTP未設定/失敗。画面の招待リンクを手動共有、または `SMTP_*` を設定 |
| ロケーションが「不明」 | ループバック/内部IP、または `npm run dev`（実IP非可視）。実IPは `npm run serve`＋TLSプロキシ |
| MFAコードが通らない | TOTPは端末時刻ずれを確認。メールは再送。最終手段は Admin が「MFA再登録」 |
| 最後のAdminを無効化できない | 仕様（最低1名のAdminを保護）。先に別のAdminを用意 |
